## Phase D — Voice pipeline, mocks, and guardrails
- [ ] Define adapter interfaces in `packages/adapters`: `SttProvider.openStream({lang,encoding:'mulaw',sampleRate:8000})` emits partial/final text, confidence and language; `LlmPlanner.plan({objective,history,whispers,tools,generationId})` supports streaming tool calls or text and cancellation; `TtsProvider.synthesize(text,{voice,lang,tone})` yields 8 kHz mulaw frames of 160 bytes; `Telephony` exposes dial, audio callback/send, DTMF, hangup, bridge and join methods.
- [ ] Provide mock STT/LLM/TTS/telephony as defaults. Synthetic callee scenarios cover clinic booking, 3-level IVR, IVR loop, callee hangup, hold exceeding timeout, OTP request, rejection then alternative. The mock conference must be usable in tests/demo.
- [ ] Real provider adapters are env-gated only; verify current provider documentation and do not invent endpoints. Real calling is disabled by default, only to operator-controlled or consenting test numbers, with explicit config, server-side rate limits and number blocklist. No cold-calling businesses.
- [ ] Inbound audio is base64 mulaw, mono 8 kHz, 20ms/160-byte frames; jitter buffer reorders sequence data at 40–80ms and forwards within ≤2 frames. Outbound pacing is exactly 20ms from a monotonic clock, has immediate queue flush on barge-in, performs per-frame mulaw encoding if TTS returns PCM, and never resamples mid-pipeline.
- [ ] Track VAD for callee, user and agent playback. Callee turn ends after ≥400ms silence and a complete clause, not a trailing “and/but/um”; short low-energy backchannels (<~500ms “haan/uh-huh/okay”) are not turns. Callee barge-in speech >~300–500ms stops TTS and switches state. User priority over overlapping callee speech is configurable.
- [ ] Implement states `INITIATED`, `IVR_NAVIGATING`, `ON_HOLD`, `CALLEE_SPEAKING`, `AGENT_SPEAKING`, `USER_WHISPERING`, `PATCHING_IN`, `PATCHED_IN`, `ENDING`, `ENDED`; support all transitions specified in the brief, reject illegal transitions, and log timestamp/trigger/from/to in `call_events`.
- [ ] Planner tools: `speak_to_callee(text,tone neutral|polite|firm|apologetic)`, `speak_to_user(text)`, `send_dtmf(digits ^[0-9*#]+$)`, `wait(seconds ≤180)`, `patch_in_user(reason)`, `end_call(reason)`. Agent is brief/natural, language-matches, discloses it is AI at call start, answers truthfully, never claims to be the user, never shares personal information without permission, immediately patches in for OTP/password/payment/KYC, never speaks over hold music, asks once more after twice-unclear then patches in, keeps utterances under ~15s, repeats bookings before ending, and prioritizes whisper corrections.
- [ ] Every plan request increments `generationId`; whisper mid-generation cancels the request and replans with the whisper; stale responses are discarded. Partial transcripts may pre-warm likely tools and greeting TTS may pre-generate during dialing/holding.
- [ ] Detect IVR via scripted phrase/menu/voice cues; prefer voice keywords or DTMF as supported; cap depth at ~5 then press 0; detect loops and try 0/# once before honestly reporting. Detect hold via audio/spectral/transcript cues, silence outbound audio, time out around 3 minutes, resume on human speech.
- [ ] Whisper audio uses a separate STT stream; injected as a timestamped `[USER WHISPER]`; brief ack goes only to the user; corrected message is spoken to callee; gate user VAD during acknowledgement playback.
- [ ] Patch-in triggers include OTP/KYC/payment, repeated confusion, user action/phrase, and consent decisions. Agent announces transfer, bridges the user without dropping the callee, supports silent note-taker if possible, and logs PATCHED_IN. Mock behavior is testable.
- [ ] Post-call: generate a <30s spoken summary; store summary/transcript/outcome (`success|failed|patched|no_answer|hung_up`); store recording URL only with consent; redact PII before storage/logging.
